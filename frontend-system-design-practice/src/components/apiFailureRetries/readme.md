## Day - 06.How would you handle API failures and retries gracefully?

### এপিআই রেজিলিয়েন্স এবং রিট্রাই স্ট্র্যাটেজি (A-Z গাইড)
এই গাইডটি মূলত আধুনিক ফ্রন্টএন্ড অ্যাপ্লিকেশনে (বিশেষ করে RTK Query এবং Redux Toolkit ব্যবহার করে) কীভাবে এপিআই ফেইলিওর, রিট্রাই এবং সার্কিট-ব্রেকিং হ্যান্ডেল করতে হয় তার উন্নত কৌশলগুলো নিয়ে আলোচনা করে।

**সূচিপত্র**
1. মূল তত্ত্ব: রেজিলিয়েন্স প্যাটার্নস
2. এক্সপোনেনশিয়াল ব্যাকঅফ এবং জিটার
3. সার্কিট ব্রেকার প্যাটার্ন
4. RTK Query-তে বাস্তবায়ন
5. আইডেমপোটেন্সি এবং ডেটা ইন্টিগ্রিটি
6. অপটিমিস্টিক ইউআই আপডেট
---
**১. মূল তত্ত্ব (Core Theory)**
একটি ডিস্ট্রিবিউটেড সিস্টেমে নেটওয়ার্ক সবসময় নির্ভরযোগ্য নয়। Graceful Degradation (সিস্টেমের আংশিক ব্যর্থতা সত্ত্বেও সচল থাকা) নিশ্চিত করে যে একটি মাত্র এপিআই ফেইল করার কারণে যেন পুরো অ্যাপটি ক্র্যাশ না করে।

- ট্রানজিয়েন্ট এরর (Transient Errors): সাময়িক সমস্যা (যেমন: 503 Service Unavailable, Timeouts)। এগুলোর ক্ষেত্রে Retry করা উচিত।

- পার্মানেন্ট এরর (Permanent Errors): ক্লায়েন্ট-সাইড ভুল (যেমন: 401 Unauthorized, 404 Not Found)। এগুলোর ক্ষেত্রে Retry করা একদমই উচিত নয়।
---
**২. এক্সপোনেনশিয়াল ব্যাকঅফ এবং জিটার (Backoff & Jitter)**
সার্ভার ডাউন থাকলে প্রতি ১ সেকেন্ড পরপর রিট্রাই করা সার্ভারের জন্য ক্ষতিকর। আমরা Exponential Backoff ব্যবহার করি যাতে প্রতিটি চেষ্টার মাঝখানে বিরতি বাড়ানো যায়।

- গাণিতিক সূত্র:$$Delay = \min(Cap, (Base \times 2^{attempt})) + Jitter
- Backoff: এটি সার্ভারকে "Thundering Herd" (হঠাৎ করে হাজার হাজার রিকোয়েস্টের চাপ) থেকে রক্ষা করে।
- Jitter: এটি রিট্রাইয়ের সময়ে সামান্য র‍্যান্ডম সময় (±১০০ মিলি-সেকেন্ড) যোগ করে, যাতে সব ইউজার একসাথে সার্ভারে রিকোয়েস্ট না পাঠায়।
---
**৩. সার্কিট ব্রেকার প্যাটার্ন (Circuit Breaker)**
যদি একটি এপিআই বারবার ফেইল করে, তবে আমরা "সার্কিট ট্রিপ" করি যাতে নির্দিষ্ট সময়ের জন্য সেই এপিআই-তে আর রিকোয়েস্ট না যায়।

- Closed: সিস্টেম ঠিক আছে, রিকোয়েস্ট যাচ্ছে।
- Open: রিকোয়েস্ট সরাসরি আটকে দেওয়া হচ্ছে (সার্ভারকে রিকভার করার সুযোগ দেওয়া হচ্ছে)।
- Half-Open: একটি টেস্ট রিকোয়েস্ট পাঠিয়ে দেখা হয় সার্ভার ঠিক হয়েছে কি না।

**৪. RTK Query-তে বাস্তবায়ন**
RTK Query-তে retry ইউটিলিটি ব্যবহার করে খুব সহজেই এটি হ্যান্ডেল করা যায়।

```js
অ্যাডভান্সড র‍্যাপার উদাহরণ:
TypeScript
import { createApi, fetchBaseQuery, retry } from '@reduxjs/toolkit/query/react';

// staggered retry লজিক দিয়ে baseQuery তৈরি
const baseQueryWithRetry = retry(
  async (args, api, extraOptions) => {
    const result = await fetchBaseQuery({ baseUrl: '/api' })(args, api, extraOptions);

    // Fail-Fast: ৪০১ বা ৪০৪ এরর হলে রিট্রাই বন্ধ করে দাও
    if (result.error?.status === 401 || result.error?.status === 404) {
      retry.fail(result.error);
    }
    return result;
  },
  { maxRetries: 5 } // সর্বোচ্চ ৫ বার চেষ্টা করবে
);

export const apiSlice = createApi({
  baseQuery: baseQueryWithRetry,
  endpoints: (builder) => ({
    getData: builder.query({ query: () => '/data' }),
  }),
});
```

**৫. আইডেমপোটেন্সি এবং ডেটা ইন্টিগ্রিটি (Idempotency)**
POST বা PUT রিকোয়েস্টের ক্ষেত্রে রিট্রাই করা ঝুঁকিপূর্ণ হতে পারে (যেমন: ভুল করে দুইবার পেমেন্ট কেটে নেওয়া)।

* সমাধান: Idempotency Keys ব্যবহার করুন।

- ফ্রন্টএন্ড থেকে একটি ইউনিক আইডি তৈরি করুন: X-Idempotency-Key: "uuid-123"।
- ব্যাকএন্ড যদি একই কি (key) দ্বিতীয়বার দেখে, তবে সে নতুন করে প্রসেস না করে আগের রেজাল্টটিই রিটার্ন করবে।
---
**৬. অপটিমিস্টিক ইউআই আপডেট (Optimistic UI)**
ইউজার এক্সপেরিয়েন্স উন্নত করতে এপিআই রেসপন্স আসার আগেই ইউআই আপডেট করে ফেলাকে অপটিমিস্টিক আপডেট বলে।

* কেন এটি করবেন?

- ইউজার মনে করবে অ্যাপটি খুব ফাস্ট।

- যদি রিট্রাই করার পরও এপিআই ফেইল করে, তবে onQueryStarted ব্যবহার করে আগের স্টেটে ফিরে যাওয়া (Rollback) যায়।
```js
async onQueryStarted({ id, ...patch }, { dispatch, queryFulfilled }) {
  const patchResult = dispatch(
    api.util.updateQueryData('getPost', id, (draft) => {
      Object.assign(draft, patch) // আগেভাগেই ইউআই আপডেট
    })
  )
  try {
    await queryFulfilled // এপিআই রেসপন্স এর অপেক্ষা
  } catch {
    patchResult.undo() // ফেইল করলে আগের অবস্থায় ফিরে যাও
  }
}
```

##### সামারি চেকলিস্ট
- এরর চেনা: শুধুমাত্র 5xx এবং টাইমআউট এরর রিট্রাই করুন।
- ব্যাকঅফ: এক্সপোনেনশিয়াল ডিলে ব্যবহার করুন।
- সার্কিট ব্রেকার: বড় ধরনের ফেইলিওর থেকে ইনফ্রাস্ট্রাকচার বাঁচান।
- ফেইল-ফাস্ট: ক্লায়েন্ট এরর (401/404) হলে সাথে সাথে রিট্রাই বন্ধ করুন।
- নিরাপত্তা: মিউটেশন রিকোয়েস্টের ক্ষেত্রে আইডেমপোটেন্সি কি ব্যবহার করুন।
